The controller now checks that exact UUID and rejects either target-path collision or same-source/different-UUID collision before submission. The public proof also enumerates all pool names; an unreconciled additional pool blocks the fixed controller. A successful native create may add only its exact deterministic UUID after durable intent, while the old pool's definition must remain unchanged.

If the old pool is the same NFS source under a different UUID, the proposed existing-export registration is **blocked**, not safe merely because the Python wrapper contains no delete command. The next proposal must be either an explicitly reviewed unused-pool metadata migration after verifying no references/mount users, or a separate owned primary subdirectory with its own deterministic identity and verified NFS reachability. Neither migration nor subdirectory creation is authorized or executed by this read-only/source slice. The old pool may instead be unrelated; exact fresh public source/target/type evidence decides that case.
