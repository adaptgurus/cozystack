# DC host read-only inventory

Status: `SOURCE_COMPLETE`. Base: cozystack `4c4268cd012ab99b75d85c6909db6e65a6c26aed`, fetched before creating `codex/dr-dc-r0-inventory`. No push, workflow dispatch or live mutation was performed by this source task.

The existing Rocky R0 workflow uses protected repository host/user/password secrets but disables SSH host verification and deletes its temporary known_hosts. Historical DC workflows inspected use either that pattern or `UserKnownHostsFile=NUL`; tracked evidence contains no independently established DC host public key. The separate DR host's key cannot identify DC. The new dispatch-only workflow requires `LAYERSENTRY_DC_SSH_KNOWN_HOSTS` with independently verified lines of the form `10.10.10.14 ssh-ed25519 BASE64_PUBLIC_KEY` (also accepts RSA and nistp256 ECDSA). It never discovers or automatically trusts a key. Missing or invalid trust produces a named unmet prerequisite before SSH/password use. Exact `LAYERSENTRY_ROCKY_R0_HOST=10.10.10.14` and `LAYERSENTRY_ROCKY_R0_USERNAME=root` are required; the password remains runtime-only.

The protected runner wrapper uses strict SSH host checking, disables user SSH configuration and alternate global trust, preserves the existing password/SSH_ASKPASS transport, and keeps the helper/known_hosts in an ACL-restricted temporary directory. The askpass helper reads the password through an environment API rather than interpolating it into CMD. It streams the versioned Python collector through SSH without uploading guest files. No authorized_keys, console, network, service, storage or config mutations are performed. Raw SSH errors, remote exceptions and unvalidated output are not published; summary evidence records the failed prerequisite or SSH exit code.

The collector checks root and local ownership of the exact DC IP before inventory. Named data includes hostname/Rocky package/kernel, IPv4 interfaces/bridges/ports, mounts without mount options, block devices, named storage-path free space, NFS exports/service, management/agent/libvirt packages/services, read-only libvirt domain/pool names and secondary-storage System VM template filenames/sizes. No config, log, template metadata or disk contents are read. Per-command deadlines, output limits, list/scan bounds and a 120-second remote deadline constrain collection. Unavailable/timeout/truncated results stay explicit. These observations do not assert CloudStack storage registration, template validity, mount accessibility from DR, backup success or recovery readiness.
