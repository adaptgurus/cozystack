## Bounded implementation and trust decision

The new `.github/workflows/layersentry-dc-console-trust.yml` has three explicitly selected phases and shares `layersentry-live-environment` serialization. Checkout pins `github.sha`; dispatch selects a phase, while the isolated `codex/dr-dc-trust` push path requires exactly one newly added immutable phase request with the exact target, VM and phase-specific authorization. No push automatically selects a mutation. It binds host `TESTSER`, VM name `sen`, immutable UUID `29ba176b-b81a-4f47-8f51-ecec869f247f` and Running state before observation and each keyboard action. Phase `Observe` reports only a prompt classification. Phase `Login` accepts a freshly observed empty `layersentry` login, optionally refreshes only the known kernel-output shape once, types `root`, observes the new password prompt, submits the environment-only runtime credential once, and observes an empty root shell. Existing/prefilled/unknown password prompts receive no credential. Keyboard input is never retried after any uncertain result.

Phase `Verify` requires an authenticated empty root prompt. `ssh-keyscan` obtains an **untrusted candidate**, without SSH authentication. Its exact `.14` ED25519 algorithm/base64 and binary key structure are validated; this candidate cannot authenticate any session. A fresh 128-bit random challenge and a fixed read-only program are sent through the exact-VM console. The guest independently requires root, confirms local address `.14`, walks `/etc/ssh` through `O_NOFOLLOW` directory FDs, validates root ownership/modes, opens only the regular single-link public host-key file through its directory FD, and compares its algorithm+base64 bytes to the candidate. Symlinks, hardlinks, writable keys/directories, missing identity or mismatches fail closed. No private host key or credential file is read.

The typed command encodes the fixed program, so terminal echo does not contain a plaintext success challenge. Python runs in isolated mode so environment optimization cannot disable its checks. Only executed output clears the screen and renders the challenge and address/root/key comparison result. The public key itself is compared inside the guest and is omitted from the console to avoid 80-column wrapping and fragile base64 OCR; it is retained in `verified_known_hosts` only after the exact challenge receipt succeeds. Exact OCR lines, the fresh random challenge and empty root prompt are required before publishing that file or its public screenshot. OCR uncertainty and unexpected/extra text fail closed. Public-key trust is tied to the Hyper-V identity and console channel; it is not inferred from the unauthenticated network scan.

All working captures are in an ACL-restricted temporary folder outside the upload path and are deleted on exit. Login never uploads any image, OCR transcript, keyboard arguments or raw exception. The workflow publishes only a sanitized stage/outcome; a verified public-key phase additionally publishes the known_hosts line and the allowlisted public screenshot. Logs suppress debug/verbose tracing. Credentials remain environment-only, are not interpolated into shell commands, and are cleared before exit. The workflow does not change guest SSH configuration, authorized_keys, networking, storage, packages, services or repository secrets, and never attempts password SSH.

Live username evidence showed that TypeText is incompatible with this Linux console and must never carry credentials. The script now uses the existing reviewed US-layout virtual-key mapping, extracted unchanged into a pure helper shared with `invoke-hyperv-console-command.ps1`. [Microsoft TypeKey documentation](https://learn.microsoft.com/en-us/windows/win32/hyperv_v2/typekey-msvm-keyboard) defines its virtual-key press/release contract. All ASCII is validated before input; text is bounded at 3500 characters and each key call rechecks VM identity. Shift is released after an uncertain owned operation, but no character or Enter is replayed. Login must observe the exact echoed root username before Enter and a fresh password prompt before sending a credential. [OpenSSH keyscan documentation](https://man.openbsd.org/ssh-keyscan) explicitly requires independent verification; the candidate-to-console comparison supplies that boundary here. A manual trusted console comparison remains an alternative if OCR fails; disabling host checks is not a fallback.
