# DC console username-only step

Status: `SOURCE_COMPLETE`. The integration lead inspected snapshot run `33999431879` and observed Rocky Linux 9.8 at an empty `layersentry login:` prompt. This bounded step uses that authorization only to submit the literal username `root` and Enter, then stops for review. It does not submit a password, authenticate a session, run a guest command, change SSH keys/configuration or establish host-key trust.

The workflow checks `TESTSER`, exact VM `sen` ID `29ba176b-b81a-4f47-8f51-ecec869f247f` and Running state. It captures a new console image, reuses the existing Windows OCR helper and requires the final nonblank recognized line to match the empty `layersentry login:` prompt exactly. Password/root-shell markers, prefilled/unknown prompts, OCR failure or evidence older than 30 seconds block input. It resolves the CIM keyboard through the immutable VM ID and repeats identity/freshness checks immediately before input. Microsoft documents the `Msvm_Keyboard.TypeText` input as `asciiText`; the call is pinned to `root`, followed by only virtual key 13: [Microsoft TypeText reference](https://learn.microsoft.com/en-us/windows/win32/hyperv_v2/typetext-msvm-keyboard).

Neither keyboard call is retried. A nonzero/uncertain result records `INPUT_OUTCOME_UNKNOWN`; in particular, uncertain username typing cannot fall through to Enter. After any attempted input, the wrapper captures the console again, even on failure, and missing after-image evidence fails the workflow. The summary separates attempted input, confirmed username/Enter and before/after capture, with `passwordSent=false` and `guestConfigChanged=false`. OCR is a conservative prerequisite, not a guarantee that a concurrent external console operator cannot change the prompt; global workflow serialization and the short freshness bound reduce that exposure. The lead must inspect the after image before any separately authorized next phase.

Validation: eight PowerShell wrapper fixture tests passed (10 cases), covering literal username/Enter only, password/shell/unknown/prefilled prompts, wrong VM, missing before image, uncertain typing without retry/Enter and missing after image without further input. PowerShell syntax, YAML parsing and `git diff --check` passed. These fixtures mock Hyper-V, capture and OCR; live OCR/key delivery remains `NOT_TESTED` by this source task. No push, dispatch or live input was performed.

The new workflow has its own-file integration push trigger and `layersentry-live-environment` serialization with cancellation disabled. Only integrate/execute once after checking current console/workflow state. A repeat at a password prompt must fail without input. There is no blind password batch and no automatic next phase.

## Guarded refresh for interleaved kernel output

The lead's closer inspection of the same snapshot identified kernel messages interleaved with and below `layersentry login:`, so requiring the last OCR line to be the prompt would block that known console state. The additive correction permits exactly one empty Enter only when one recognized `layersentry login:` line has no supplied username and its trailing/succeeding nonblank text consists exclusively of bracketed numeric kernel-timestamp lines. Password/shell markers or any unknown trailing text deny refresh. After refresh, a new capture and OCR must show the strict empty last-line login prompt before `root` and Enter; an unchanged/unknown/password prompt stops without retry or username. Refresh attempt, confirmed Enter and refreshed capture have separate evidence fields. A nonzero refresh return value is an unknown input outcome and cannot advance.

Validation of the corrected script: all 12 PowerShell fixture tests passed (16 cases), including the observed inline-plus-following kernel-log shape, unknown trailing text, supplied username, password prompt, uncertain refresh and unsuccessful prompt refresh. PowerShell syntax and diff checks passed. No live input was performed. The integration lead remains responsible for reviewing the after image and authorizing any later password phase separately.
