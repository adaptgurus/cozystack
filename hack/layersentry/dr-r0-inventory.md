# Read-only DR prerequisite inventory

Use the existing Windows runner workflows after reviewing and integrating the exact collector commit. These commands are dispatch instructions, not evidence of execution:

```bash
gh workflow run layersentry-cloudstack-r0-api-inventory.yml --repo adaptgurus/cozystack --ref ops/layersentry-hyperv-inventory -f target_profile=dc -f api_endpoint=http://10.10.10.14:8080/client/api
gh workflow run layersentry-cloudstack-r0-api-inventory.yml --repo adaptgurus/cozystack --ref ops/layersentry-hyperv-inventory -f target_profile=dr -f api_endpoint=http://10.10.10.20:8080/client/api
gh workflow run layersentry-dr-ui-readonly-probe.yml --repo adaptgurus/cozystack --ref ops/layersentry-hyperv-inventory
gh workflow run layersentry-dr-r0-live-inventory.yml --repo adaptgurus/cozystack --ref ops/layersentry-hyperv-inventory
```

The API collector requires existing scoped `LAYERSENTRY_CLOUDSTACK_API_KEY`/`LAYERSENTRY_CLOUDSTACK_SECRET_KEY` for DC, and independent `LAYERSENTRY_DR_CLOUDSTACK_API_KEY`/`LAYERSENTRY_DR_CLOUDSTACK_SECRET_KEY` for DR. Missing DR credentials never fall back to DC credentials. It does not register keys or add a login fallback. Each profile is bound to its exact disposable-lab endpoint; arbitrary destinations, URL credentials/query strings and redirects are rejected. HTTP is the existing isolated-lab transport, not a production TLS claim. API keys remain runtime-only; response fields are projected before artifact writing, excluding template URLs, VM details/userdata and backup metadata payloads.

The API artifact includes management identities/versions, Zones/Pods/Clusters/routing hosts, primary/secondary storage, networks, templates, VMs, B&R providers/repositories/offerings/backups/configuration and recent async jobs. Management IDs are CloudStack identities, not the proprietary Support Cluster UUID, which remains `UNKNOWN`. The collector records returned/reported counts and fails with retained evidence when the single page is truncated or any optional API fails. A 431 response is a failure, not proof that a plugin is unsupported. Absence of a provider/resource is evidence of absence in the caller's visible scope, not a readiness claim. Inventory must be reviewed before mutating prerequisites; separate management databases are not automatically a native cross-Zone recovery topology.

Every collection is a JSON array for zero, one or many items; an omitted empty API collection becomes `[]`. Optional failures expose only numeric `HttpStatusCode` and `ApiErrorCode` plus an exception type. Error codes are extracted from `errorresponse` or the command-specific response envelope, using PowerShell `ErrorDetails.Message` or the Windows PowerShell response stream. Raw error bodies/messages and signed request URLs are never written to evidence. HTTP 401 and 431 are tested using a local HTTP server and the real PowerShell HTTP client. The native backup-provider collection key is `providers`, as explicitly set by `ListBackupProvidersCmd` in the exact source.

The DR SSH probe reuses `LAYERSENTRY_DR_ROCKY_HOST`, `LAYERSENTRY_DR_ROCKY_USER`, `LAYERSENTRY_DR_SSH_PRIVATE_KEY` and independently pinned `LAYERSENTRY_DR_SSH_KNOWN_HOSTS`. It checks agent/libvirt packages/services, KVM device/access, CPU virtualization flags, read-only libvirt domain listing and filesystem capacity in bytes. Missing prerequisites are recorded with return codes; SSH/transport failures still fail the workflow. The Hyper-V inventory independently records guest virtualization exposure and host-volume free space. Do not use `layersentry-dr-rocky-ssh-inventory.yml` as the generic prerequisite collector: its current body is a specialized database diagnostic.

Design: retain the existing native-list-API collector and pinned SSH transport; no controller or CloudStack core change is needed. Native command and response names were checked against the 4.22.1.1 source (`ListMgmtsCmd`, `ListBackupProvidersCmd`, `ListBackupsCmd`, `ListTemplatesCmd`, `ListNetworksCmd`, response classes and `QueryManagerImpl`). The [4.22 management API](https://cloudstack.apache.org/api/apidocs-4.22/apis/listManagementServers.html) and [provider API](https://cloudstack.apache.org/api/apidocs-4.22/apis/listBackupProviders.html) corroborate the native operations; these public pages identify themselves as 4.22.0.0, so exact patch behavior is source-checked. No architecture or knowledge-graph relationship changes. Rollback is reverting the collector commit; no guest mutation is performed by the collectors.

Offline behavioral checks run the actual workflow PowerShell against a mocked API: complete inventory and secret-field exclusion, mismatched profile, missing credentials, truncation, and optional API failure. Run `python3 hack/layersentry/test_r0_api_inventory.py` with PyYAML and PowerShell available (`POWERSHELL` may select its executable). Source verification does not establish live agent readiness, NAS recovery, independent sites or production certification. The next gate is exact-commit runner execution and review of both sites' actual prerequisites.
